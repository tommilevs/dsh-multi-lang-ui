# dsh-multi-lang-ui

**Многоязычный интерфейс и переводы сообщества для DeepSeek Harness (DSH).** Плагин сохраняет русский перевод и пользовательские функции `dsh-russian-lang`, добавляет переводы английского интерфейса самого плагина и позволяет подключать новые языковые пакеты для других плагинов.

English version: [README.en.md](README.en.md).

## Что уже включено

- Основа и функциональность [`GooDAnDReaDY/dsh-russian-lang`](https://github.com/GooDAnDReaDY/dsh-russian-lang): русский словарь ядра и плагинов, переключение RU/EN, plural-формы, типографика, коррекция раскладки, переопределения, инспектор и прежние настройки `russian-lang`.
- Полный набор словарей из исходного проекта плюс недостающие ключи ядра из установленной у автора версии 0.3.7. Сейчас это 56 пространств ядра, 130 пространств плагинов и 365 точных строк китайского интерфейса. Это объём словарей, а не обещание полного покрытия каждого релиза DSH.
- Русские словари для `@linxin666/dsh-web-all` 0.4.1: статистика использования и архив сессий.
- Русский и английский адаптеры для китайского UI `dsh-mcp-manager-ui` 1.4.0 и `@dsh-external/dsh-super-injector` 0.3.3. Они переводят только известные точные строки внутри корневых классов плагинов. Неоднозначная строка `关闭` намеренно оставлена без перевода, чтобы не путать подпись «Закрыть» со значением «Выключено».
- Раздел **Переводы сообщества / Community translations** для импорта и экспорта JSON-пакетов. Переводы — только данные: они не исполняются как код.

Нативный английский DSH остаётся языком по умолчанию и fallback. Пакеты добавляют отсутствующие переводы и переключаемые языки; они не заменяют словари ядра DSH.

## Установка

Установка из DSH: откройте **Plugins → Add** и укажите источник GitHub:

```text
github:tommilevs/dsh-multi-lang-ui
```

Перед установкой удалите `@goodandready/dsh-russian-lang`: оба пакета добавляют русские словари и конфликтуют по локали `ru`. Настройки остаются в пространстве `russian-lang`; DSH 0.1.7 отображает их как параметры профиля. После замены перезапустите DSH Desktop.

Для разработки и проверки локально используйте:

```bash
node scripts/embed-multilang.mjs
node --test test/*.test.mjs
node scripts/validate-locales.mjs
```

## Добавление перевода

Переводы находятся в `contributions/<package-id>/<locale>.json`. Для scoped-пакета путь повторяет scope, например `contributions/@scope/plugin/ru.json`. В JSON указываются версия и источник плагина, лицензия, исходные строки, перевод, а для UI без locale API — список точных DOM-подстановок с ограниченным CSS-селектором.

Подробный двуязычный формат, требования к атрибуции и шаги проверки описаны в [CONTRIBUTING.md](CONTRIBUTING.md). Локально проверьте вклад командами:

```bash
node --test
node scripts/validate-locales.mjs
```

Pull request с данными в `contributions/` проходит CI-валидацию. Workflow читает JSON как данные и запускает проверенный скрипт из целевой ветки; вклад не может добавлять исполняемый код в CI или браузер.

## Совместимость и лицензии

Плагин предназначен для актуального DSH и использует штатный API locale/settings/slots. Для плагинов с нативными словарями используйте namespace-пакеты. DOM-адаптеры — точечный fallback; если upstream меняет классы или подписи, обновите пакет под новую версию.

Код и словари, унаследованные от `dsh-russian-lang`, остаются под MIT с сохранённым уведомлением. Для каждого внешнего набора строк сохраняются источник, версия и объявленная лицензия. Подробности и известное расхождение лицензии injector-пакета перечислены в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
